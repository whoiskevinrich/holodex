# Entity components

Entity-generic (person | studio | tag) building blocks: searching for an entity, merging one
into another, and the shared video-list body for an entity's detail page.

| File | Purpose |
|---|---|
| `CategoryPicker.svelte` | Category assign/remove picker (HOLODEX-240): search-or-create (`mode="add"`) or search-only (`mode="remove"`) a category for the selected tags — single-step, no informed confirm (assign/remove are reversible, unlike merge). |
| `CollisionOfferCard.svelte` | Video composite-key collision verdict card (HOLODEX-270): "View existing video" / "Save anyway, keep both" — no merge verb, since two video files can't be folded into one record. Video-flavored sibling of `MergeOfferCard`, shown in `NameEditControl`'s same verdict slot on the Video Title mount. |
| `CompletenessSortToggle.svelte` | Owner-only "Completeness ↓/↑" segmented toggle (F55.5) for the People/Studios indexes — kept separate from `SortToggle` since its `PeopleTagSort` type is shared with the Tags page, which has no completeness scoring. |
| `EntityPicker.svelte` | Merge picker: search/pick another entity, then an informed confirm showing both video counts (never a silent merge). Generalized from F23's PersonPicker. |
| `EntityPickerDialog.svelte` | Local entity-search picker for the Extraction tab's People/Studio field edits — searches the app's own entities (no external round trip); confirming never writes, just hands back a name. |
| `EntityVideoMeta.svelte` | The muted video-count line under an entity's title, with its sorted provider-link badges (HOLODEX-266, ADR-083 D3/DD1) appended after a `·` separator. Shared by `EntityVideos`' own default title block and the person page's `hero` snippet, which renders its own title/portrait layout but wants this identical meta row beneath it. Optional `ref` (F60) appends `RefChip` as the row's last item. |
| `EntityImageSlot.svelte` | Upload/replace/remove control for one of an entity's single-slot image roles (HOLODEX-286) — generalized from the byte-identical Studio (F51, icon/logo/poster) and Film (F56/HOLODEX-280, poster/thumb) versions. Generic over the role string (`generics="TRole extends string"`); the caller passes its own `api.uploadXImage`/`api.deleteXImage` as the `upload`/`remove` props. `fit` (F59/ADR-089 D4) selects `object-contain` (default) or `object-cover`: contain suits a slot whose ratio matches its art (a 2:3 poster in a 2:3 frame), cover is for one that deliberately differs — the film banner shows a ~16:9 backdrop in an 8:3 band, which contain pillarboxes against the light plate. The contain path also insets the image (`p-1` row / `p-0.5` frame), and that inset IS the visible "border" — the plate showing through; cover has none. No gallery/promote/viewer, unlike Person's image system (`person/PersonGallery.svelte` et al.), which stays separate since it has a capped gallery, dedup, and promote this simple "one row per role" shape doesn't. |
| `EntityVideos.svelte` | Shared body for person/[id], studio/[id], and tag/[id] detail pages: back-link, title, video count, the video grid, scroll restoration (HOLODEX-248, keyed by the `scrollKey` prop), and NS6 in-place video-title filtering off the shared nav search box (HOLODEX-249) — all three callers pass their raw `videos`/`empty`, this component owns the `navSearch`-driven filtering and empty-state swap. Optional `hero`/`detail`/`footer` snippets — `footer` (F56) renders after the grid, used for the films row. |
| `FilmsRow.svelte` | Films row (F56, design handoff §5): small horizontal shelf of poster-thumb cards linking to each film, passed into `EntityVideos`' `footer` snippet by person/studio/tag detail pages. Renders nothing when `films` is empty — callers gate on `films_enabled` + non-empty before passing data, never an informational dead end. |
| `MergeCanonicalDialog.svelte` | Step two of a multi-select merge: "keep which name?" — the rest fold into the survivor. Shared by /people and /tags. |
| `DisplayNameLine.svelte` | The name field's curation line under a Person/Studio/Film heading (F60 RD10, HOLODEX-378): "In files as `<canonical>`" (films: "On record as") plus the name field's `SourceBadge` for the owner, rendered only when the resolved spelling differs from the canonical column — **owner-only**: visitors see the heading alone (owner ruling: they don't need to know about the files; the visitor-facing value is the resolved name, so the routes content rule is satisfied by the heading). With no decision standing the owner gets a quiet link in the same slot that opens the badge's chip row in place — it **names the provider spelling on offer** (`Display as Ana Keßler (tmdb)…`; bare `Display as…` when none differs), because QA 4.3's first pass showed that at rest nothing else says a second spelling exists; focus hands across the link↔badge swap. Two verbs, two affordances: this line is "Display as" (a DB-only decision), the docked pencil beside the heading is "Rename in files" — and once a decision stands the record spelling on this line is the owner's visible trigger for that same form (`onRename` → `NameEditControl.open()`; the pencil is hover-hidden beside a heading that no longer shows the record spelling, QA 4.3 follow-up). Never mount the name field in a page's field list — this is its one mount. |
| `MergeOfferCard.svelte` | Homonym-collision verdict card (HOLODEX-269, extracted from `AliasPanel`): "is this the same {noun}?" merge-in / keep-separate choice, shown on an exact-name collision from an alias add or a rename. Presentational only — caller owns busy/error state and the merge/keep-separate calls. Shared by `AliasPanel`'s alias-add flow and `NameEditControl`'s rename flow. |
| `NameEditControl.svelte` | Docked-pencil rename affordance (HOLODEX-269): at rest, renders identically to a non-owner's view; on owner hover/focus, a low-opacity pencil brightens, opening an inline rename. `pencilAlwaysVisible` (Video Title only) skips the hover/focus reveal and keeps the pencil fully opaque at rest — Person/Studio/Tag headers omit it and keep the default hover reveal. On a 409 collision, shows a caller-supplied `verdict` snippet (typically `MergeOfferCard`, or `CollisionOfferCard` for Video) inline instead of a modal. Generic over the conflict payload (HOLODEX-270, `TConflict = EntityRef` by default) so Video Title can supply `VideoCollisionRef` with no change to the Person/Studio/Tag call sites. Shared by Person/Studio/Tag detail-page headers, the Video Title heading, and the Film year (F59/HOLODEX-317). **Not name-only despite the name:** the Film year mount is the first caller that is neither a name nor the page heading, and it drove three optional, defaulted widenings — `as` (the resting element, default `h1`; the year passes `p`, since the film title above already owns the page's single h1 and a year is a field value, not a heading), `editLabel` (overrides the `Rename this {label}` accessible name, which describes no action for a year), and `placeholder` (resting text when the value is empty, e.g. "No year set" — the edit input still opens empty, so the placeholder never becomes a value the owner must delete first). Every original call site is unchanged. `editValue` (HOLODEX-378) is the value the edit form opens with when the heading is not the canonical value: Person/Studio/Film headings render the *resolved* name (a display decision may pick a provider or custom spelling) while the pencil renames the canonical record, so they pass `name={displayName} editValue={canonical}` and "unchanged" is judged against `editValue`. `open()` (exported, HOLODEX-378) opens the same form from outside via `bind:this` — `DisplayNameLine` is the one caller. Before this, the Film page **hand-rolled** `name-edit-row`/`name-edit-pencil` for its studio row without importing the component — if you are about to copy those classes, mount this instead. |
| `PeopleGrid.svelte` | Reusable People/Cast grid section: title + poster-tile grid (`grid-cols-3/4/6`, matching Films' tile size) + optional owner editing. Extracted from the Media detail page's People section; the Film detail page's Cast section (a read-only derived union of its scenes' people) now renders through the same component by omitting `attach`/`detach` — editing (per-tile remove badge + `PersonPicker` add tile) only appears when both are supplied. Owns the whole section including its `{#if}` visibility gate, not just the read-only tile shape (unlike `StudioLinkCard`, which stays a bare per-item card beside a separately-mounted `StudioPicker`) — People is a multi-item grid with per-item remove baked in, closer to Film's own tile shape than to Studio's single-value field. |
| `PersonPicker.svelte` | People relationship-edit popover (HOLODEX-272), mounted by `PeopleGrid` rather than directly by pages: a `PickerShell` popover opened from either a docked "Add person" dashed poster-tile (`hasPeople=true`, sits inside the grid beside real poster tiles) or a bare `+ Add person` text CTA (`hasPeople=false`, HOLODEX-289-style — an empty grid's lone dashed tile with nothing beside it read as less fluid than text) — the multi-select sibling of `StudioPicker` (shows the video's already-attached people, each independently removable, alongside search/create). Every result row requires an explicit Actor/Director role choice before commit; stays open across commits instead of closing on the first one. Commits through the video detail page's `attachPerson`/`detachPerson` functions (`media/[id]/+page.svelte`), passed through `PeopleGrid`, which `POST /media/{id}/curation`. Unlike `StudioPicker` it has no `verdict` prop — a conflict just closes the popover, and the page renders the shared `CollisionOfferCard` where the tile was, since the grid's own remove control shares the same attach/detach calls with no `PersonPicker` instance to render into. |
| `PickerShell.svelte` | Shared dialog chrome for `EntityPicker`/`CategoryPicker`: backdrop, `role="dialog"` wrapper, focus trap, trigger-focus save/restore, Escape-to-close, rise-in animation. Title/body are step-specific, passed as snippets. |
| `StudioLinkCard.svelte` | Reusable read-only studio display (HOLODEX-290): icon (monogram fallback) + linked name + video count, one card per studio. Replaces the ad hoc comma-joined text links the Media and Film detail pages each grew independently — those pages keep their own `StudioPicker`/`FilmStudioCascadeDialog` edit affordances beside it unchanged. No owner/edit/busy state of its own; takes a `Studio` as-is. |
| `StudioPicker.svelte` | Studio relationship-edit popover (HOLODEX-271): docked-pencil affordance replacing `SourceSelect`'s Studio radiogroup on the video detail page — known-candidate chips (via `sourceChips`), full-library search, and an inline create-fallback, all committing through the video detail page's `decideStudio`/`saveStudioAnyway` functions (`media/[id]/+page.svelte`), which call `PUT /media/{id}/fields/studio/decision`. Runs the same HOLODEX-270 collision check as Title (via its caller-supplied `decide`) and shows `CollisionOfferCard` through the same generic verdict-snippet mechanism `NameEditControl` uses. The trigger itself branches on the caller-supplied `hasStudio` (HOLODEX-289): the docked pencil once a studio is linked, or a `+ Add studio` text CTA (matching Tags' `+ Add tag`) when none is — a bare pencil floating with no linked name for visual anchor was undiscoverable. |
| `TagLinkChip.svelte` | Reusable tag display (HOLODEX-292): linked name + provenance suffix (`·file`/`·manual`/`·provider`) + optional remove control, one chip per tag. Owner vs. read-only is decided by whether the caller passes `onremove` (no separate `isOwner` boolean). Replaces three previously-inconsistent inline chip styles the Media (owner and visitor branches disagreed with each other) and Film detail pages each grew independently; both now share the same `rounded-full border-rule bg-surface-2` shape. The add-tag control itself (search/create popover) stays a separate component, `TagPicker.svelte` (HOLODEX-287/ADR-088) — this component owns only the per-tag chip, not the "+ Add tag" affordance. |
| `RefChip.svelte` | Copyable `kind:id` reference handle (F60 RD1 / HOLODEX-374): a `btn-pill` mono chip mounted as the **last item of each detail page's existing meta line** (people/studios via `EntityVideoMeta`'s `ref` prop; tags, films and media inline). Click/Enter copies, "Copied" for 1.5 s with an `aria-live` announcement; a rejected clipboard API selects the text in place instead of silently doing nothing. Visible to visitors — a ref is not a mutation. Takes the payload's `ref` string as-is and never parses or builds one; only `internal/api/ref.go` splits on the colon. |
| `SearchResultsPanel.svelte` | Grouped/tabbed search results (NS1/NS5, HOLODEX-249) — the All/People/Videos/Studios/Tags tab row + capped result rows, roving tabindex. Shared by the nav box's live-typing dropdown (`variant="dropdown"`) and `/search`'s page body (`variant="page"`), per "reuse, don't fork." Spans video results too, not just person/studio/tag. `showResults=false` (NS2) renders only the tab row — used while a scoped page (Media/People/Studios/Tags) is filtering its own grid in place, so the owner can still tap another tab to preview it without the results body doubling what the page is already showing. |

## Rules

- **`NameEditControl`'s `trailing` slot is for content that never needs to wrap** (a flag row, a
  short badge). Its at-rest heading row is deliberately `flex` *without* `flex-wrap` — HOLODEX-356:
  the name breaks words and the pencil stays docked — so anything in that slot can only take width
  *from* the heading; a wrapping pill there squeezed a four-letter title to one letter per line at
  375px (HOLODEX-377). Content that should drop beneath the title when it doesn't fit goes in a
  flex-wrap row the *page* owns around the control (media page's edition pill is the model: the
  control in a `min-w-0 max-w-full` item, the pill `shrink-0 max-w-full wrap-anywhere`).
