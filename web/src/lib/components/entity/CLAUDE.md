# Entity components

Entity-generic (person | studio | tag) building blocks: searching for an entity, merging one
into another, and the shared video-list body for an entity's detail page.

| File | Purpose |
|---|---|
| `CategoryPicker.svelte` | Category assign/remove picker (HOLODEX-240): search-or-create (`mode="add"`) or search-only (`mode="remove"`) a category for the selected tags — single-step, no informed confirm (assign/remove are reversible, unlike merge). |
| `CollisionOfferCard.svelte` | Video composite-key collision verdict card (HOLODEX-270): "View existing video" / "Save anyway, keep both" — no merge verb, since two video files can't be folded into one record. Video-flavored sibling of `MergeOfferCard`, shown in `NameEditControl`'s same verdict slot on the Video Title mount. |
| `CompletenessSortToggle.svelte` | Owner-only "Completeness ↓/↑" segmented toggle (F55.5) for the People/Studios indexes — kept separate from `SortToggle` since its `PeopleTagSort` type is shared with the Tags page, which has no completeness scoring. |
| `EntityPicker.svelte` | Merge picker: search/pick another entity, then an informed confirm showing both video counts (never a silent merge). Generalized from F23's PersonPicker. |
| `EntityPickerDialog.svelte` | Local entity-search picker for the Extraction tab's People/Studio field edits — searches the app's own entities (no external round trip); confirming never writes, just hands back a name. |
| `EntityVideoMeta.svelte` | The muted video-count line under an entity's title, with its sorted provider-link badges (HOLODEX-266, ADR-083 D3/DD1) appended after a `·` separator. Shared by `EntityVideos`' own default title block and the person page's `hero` snippet, which renders its own title/portrait layout but wants this identical meta row beneath it. |
| `EntityVideos.svelte` | Shared body for person/[id], studio/[id], and tag/[id] detail pages: back-link, title, video count, the video grid, scroll restoration (HOLODEX-248, keyed by the `scrollKey` prop), and NS6 in-place video-title filtering off the shared nav search box (HOLODEX-249) — all three callers pass their raw `videos`/`empty`, this component owns the `navSearch`-driven filtering and empty-state swap. Optional `hero`/`detail`/`footer` snippets — `footer` (F56) renders after the grid, used for the films row. |
| `FilmsRow.svelte` | Films row (F56, design handoff §5): small horizontal shelf of poster-thumb cards linking to each film, passed into `EntityVideos`' `footer` snippet by person/studio/tag detail pages. Renders nothing when `films` is empty — callers gate on `films_enabled` + non-empty before passing data, never an informational dead end. |
| `MergeCanonicalDialog.svelte` | Step two of a multi-select merge: "keep which name?" — the rest fold into the survivor. Shared by /people and /tags. |
| `MergeOfferCard.svelte` | Homonym-collision verdict card (HOLODEX-269, extracted from `AliasPanel`): "is this the same {noun}?" merge-in / keep-separate choice, shown on an exact-name collision from an alias add or a rename. Presentational only — caller owns busy/error state and the merge/keep-separate calls. Shared by `AliasPanel`'s alias-add flow and `NameEditControl`'s rename flow. |
| `NameEditControl.svelte` | Docked-pencil rename affordance (HOLODEX-269): at rest, renders identically to a non-owner's view; on owner hover/focus, a low-opacity pencil brightens, opening an inline rename. On a 409 collision, shows a caller-supplied `verdict` snippet (typically `MergeOfferCard`, or `CollisionOfferCard` for Video) inline instead of a modal. Generic over the conflict payload (HOLODEX-270, `TConflict = EntityRef` by default) so Video Title can supply `VideoCollisionRef` with no change to the Person/Studio/Tag call sites. Shared by Person/Studio/Tag detail-page headers and the Video Title heading. |
| `PersonPicker.svelte` | People relationship-edit popover (HOLODEX-272): a docked "Add person" dashed tile opening a `PickerShell` popover — the multi-select sibling of `StudioPicker` (shows the video's already-attached people, each independently removable, alongside search/create). Every result row requires an explicit Actor/Director role choice before commit; stays open across commits instead of closing on the first one. Commits through the video detail page's `attachPerson`/`detachPerson` functions (`media/[id]/+page.svelte`), which `POST /media/{id}/curation`. Unlike `StudioPicker` it has no `verdict` prop — a conflict just closes the popover, and the page renders the shared `CollisionOfferCard` where the tile was, since the grid's own remove control shares the same attach/detach calls with no `PersonPicker` instance to render into. |
| `PickerShell.svelte` | Shared dialog chrome for `EntityPicker`/`CategoryPicker`: backdrop, `role="dialog"` wrapper, focus trap, trigger-focus save/restore, Escape-to-close, rise-in animation. Title/body are step-specific, passed as snippets. |
| `StudioPicker.svelte` | Studio relationship-edit popover (HOLODEX-271): docked-pencil affordance replacing `SourceSelect`'s Studio radiogroup on the video detail page — known-candidate chips (via `sourceChips`), full-library search, and an inline create-fallback, all committing through the video detail page's `decideStudio`/`saveStudioAnyway` functions (`media/[id]/+page.svelte`), which call `PUT /media/{id}/fields/studio/decision`. Runs the same HOLODEX-270 collision check as Title (via its caller-supplied `decide`) and shows `CollisionOfferCard` through the same generic verdict-snippet mechanism `NameEditControl` uses. |
| `SearchResultsPanel.svelte` | Grouped/tabbed search results (NS1/NS5, HOLODEX-249) — the All/People/Videos/Studios/Tags tab row + capped result rows, roving tabindex. Shared by the nav box's live-typing dropdown (`variant="dropdown"`) and `/search`'s page body (`variant="page"`), per "reuse, don't fork." Spans video results too, not just person/studio/tag. `showResults=false` (NS2) renders only the tab row — used while a scoped page (Media/People/Studios/Tags) is filtering its own grid in place, so the owner can still tap another tab to preview it without the results body doubling what the page is already showing. |
