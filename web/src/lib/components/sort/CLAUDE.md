# Sort components

Sort and display controls shared across the browse/people/tags index pages.

| File | Purpose |
|---|---|
| `ListToolbar.svelte` | The one list toolbar (F73, `docs/design/list-toolbar-handoff.md`): layout only, no state. One row that never wraps — `[sort] [reroll?] [filters?] ··ml-auto·· [view?] [⋯?]` — then the chips row (with an optional `chipsEnd` after Clear, F87's Edit as text) and the `aria-live` count line. Below `sm`, `reroll` moves into ⋯ when the page has one (375 px budget). State lives in `#lib/listState` (ADR-114). Also rendered by `entity/EntityVideos` with the sort slot alone (HOLODEX-38). |
| `FilterPanel.svelte` | Filters slot: `FiltersButton` + one panel shown two ways — a non-modal popover from `sm` up, a modal bottom sheet (focus trap, Done / Clear all / live count) below. Fields apply live; no Apply button. The sheet **contains** scroll rather than locking the document (owner's pick): `touch-none` on the backdrop, `overscroll-contain` on the sheet — don't add a `<html>` overflow lock. |
| `FiltersButton.svelte` | "Filters · n" trigger; below `sm` a funnel + count. Accent when any filter is active. |
| `FilterChip.svelte` | One removable active-filter or entity-scope chip (`kind`), label truncated at 12rem. `negated` is an F87 NOT condition: the outlined accent chip (`docs/design/query-language-handoff.md`). F89: `ownerOnly` draws a key before the label, `problem` is the warn chip a refusal names, and no `onremove` is read-only. |
| `QueryChipGroup.svelte` | One F87 OR group in the chips row: an inset box of `FilterChip` members joined by `or`, an AND set in muted `( … + … )`, one group `×`. Built from `lib/query.ts`'s chip model; wraps as one unit. |
| `QueryChips.svelte` | A query's chips for a chips row, from `#lib/parsedExpr`'s model: `FilterChip`s, `QueryChipGroup`s or `AdvancedQueryRow`. Browse and the playlist page render it; no `onremove` is read-only. |
| `QueryField.svelte` | A page-owned F87 query field (F89 handoff): the nav box's look and `QuerySuggestPanel` over its own `QueryAssist`, so it never touches `navSearch`. Enter applies; `apply()` is exported for a Save that applies first. |
| `MediaFilterFields.svelte` | The media Filters panel's fields (Resolution, Year, Duration, mapped facets) over a query and a setter: browse's list and the playlist editor's draft. |
| `CapSelect.svelte` | A smart playlist's cap (F89 P0-2): a compact select in `SortDropdown`'s look. |
| `AdvancedQueryRow.svelte` | An F87 query the chips can't draw (past one OR level): `Advanced query` plus the canonical text, truncated, and its own `Edit as text`. Never a partial chip set. |
| `PageActions.svelte` | The owner ⋯ page-actions menu (Merge people, Manage tags, Save as playlist…); `compactOnly` items show below `sm` only. Items take an optional muted `hint` and an `icon` snippet. `face` + `triggerClass` replace the ⋯ trigger's look so another control can hang this same menu off itself (`video/PlaySplitButton`'s caret, F75). Reuse it; don't write a second menu. ↓ on the trigger opens it. |
| `DensitySlider.svelte` | Grid-density control shared by the media list and the People poster index (both drive the site-wide `mediaDensity`). Its range spans `DENSITY_MIN..capForWidth(viewport)`, not `..DENSITY_MAX`, so no stop is inert; hides itself when the viewport allows no choice. Optional `label` renders the caption — and its reserved width — that the media list wants and the People row deliberately omits. |
| `SortDropdown.svelte` | The sort `<select>` for every list. `options` defaults to `MEDIA_SORTS` (`lib/filters.ts`); the entity lists live in `lib/listState.ts`. Owner-only entries go in a trailing `Owner` optgroup. `extra` prepends page-specific entries (the playlist page's `manual` — F69). `compact` is the ListToolbar form (sr-only caption, 32 px, can shrink); `onchange` is where the page records the preference — never an effect (ADR-114 D3). Keep labels ≤ 20 characters: a native select is as wide as its widest option. |
| `ListTable.svelte` | The shared Table view (F82, `docs/design/list-views-handoff.md`): one fixed-layout `<table>` of 44px hairline rows; the page passes `columns` (a `ColumnSpec` plus a `cell` snippet) and nothing else differs between pages. Rules are pure in `lib/listTable.ts`: owner-only columns never reach a visitor, `keepBelow` drops a column below `sm`/`lg` (never a sideways scroll), and a header is a button only when the page's Sort offers its sort — a click calls `onsort` with that entry, so the toolbar keeps the one sort (HOLODEX-473); `aria-sort` follows. The first cell holds the item's link and a row click follows it (never one inside a control or a `role="menu"` panel). A column can set `noClip` (its cell isn't truncated, so a popover can open past it — the Tags owner ⋯ column) and `hideHeader` (the header is screen-reader only). Renders nothing with no items. **`window` mode (HOLODEX-601)** draws the People whole-list scroll instead of `items`: the rows near the view between two spacer rows (a real table can't take absolutely placed rows), placeholders, a retry row for a failed page, roving focus on the `<tr>`, `aria-rowcount` = total + 1 and `aria-rowindex` = index + 2. `shared/VirtualRows` is its grid twin; both are wired by `windowList()`. |
| `ViewToggle.svelte` | The View slot's segmented control for every list page (F55, F82): one `aria-pressed` cell per entry of the page's `PAGE_VIEWS` (`lib/viewPreference.svelte.ts`), 32×32 icon-only below `sm` with an `aria-label`. `onchange` fires on a click only — the page calls `writeView` there, never from an effect (F73 R7). A new view needs its label and icon added here. Replaced People's `PersonViewToggle`. |
| `SortReroll.svelte` | "Shuffle again" button shown beside the sort picker while Random is active. |
| `segmentedToggle.ts` | Shared button/wrapper classes for the segmented-toggle look — used by the Tags create form's Tag/Category switch and `ViewToggle`'s wrapper. (The F73 migration retired `SortToggle` and `CompletenessSortToggle`: sort is one `SortDropdown` value everywhere, HOLODEX-473.) |
