# Writeback components

Committing resolved values back to source: metadata file tags (F28) and person image crops
(F25.15).

| File | Purpose |
|---|---|
| `CropEditor.svelte` | Promote-with-crop editor: previews a gallery image inside the target core-role aspect frame with zoom/drag, then renders a WYSIWYG canvas crop as the uploaded image. |
| `WritebackFormDialog.svelte` | Batch writeback modal, cockpit revision (HOLODEX-400, `docs/design/writeback-cockpit-handoff.md`): every replace field whose staged value differs from the file renders its candidate chooser — `curation/SourceChipRow` for short fields, `curation/SourceRadioList` for `long_text` and for any row with a candidate a chip would truncate (`stacksCandidates`, HOLODEX-434 — a clipped value can't be compared) — and the Write button is that chooser's Confirm (picks stage locally; `submit()` decides via `needsDecision`, then enqueues one fire-and-forget write, ADR-091). The write is atomic over everything decided — no per-row checkbox and no Select all: a standing decision that lags the file always writes (`↧` glyph), an undecided row writes only once the owner picks a chip (`○` until then; picking is the confirm), gated by the pure `willWrite`. The dialog is the cockpit for the **golden record** (Holodex's truth), of which only the mapped subset reaches the file: an unmapped field keeps its chooser and its pick is saved in Holodex only (cylinder glyph, `savesDecisionOnly`; header reads `no file tag for this container`); a field written but not read back (ADR-093) shows `not read back` on its file chip, no warning line. A row matching the file sits in the `=` tier but keeps its chooser open — every cockpit row's chooser is always mounted and the undecided group has no disclosure, just a static `Not yet decided` caption (HOLODEX-434); an `in_sync`-unknown row carries a `Can't verify` note. `max-w-3xl` on wide screens; phone width is the overlay gutter's. Row-class / staged-value / decision predicates are pure in `$lib/writebackCockpit.ts`. Image rows (`poster_url`) are cockpit rows with `curation/SourceImageTiles` (HOLODEX-403): picking a provider tile decides + downloads/embeds on Write, picking `·file` is decision-only, an owner upload keeps the page (ADR-049 — placeholder tile + note), and their sync is witnessed by the write ledger (ADR-101) so a written poster reads `=` instead of re-embedding. Merge rows show their value — `⊖` read-only ("Nothing to decide here yet") until HOLODEX-401. No checkbox anywhere. |
| `WritebackBatchDialog.svelte` | N-video writeback progress dialog (HOLODEX-239): confirm → aggregate pending/running/done/failed progress bar → completion, for a tag-scoped manual sync batch (single or bulk). Sibling of `WritebackFormDialog`, not a mode of it — no per-video field list, only aggregate counts. An `initialBatch` prop (F57, HOLODEX-285) seeds progress directly for a batch a caller already started server-side (the Film-studio cascade), skipping the confirm step and `trigger()` entirely. |
