# ADR-042 — Windows `asInvoker` application manifest

**Status:** Accepted  
**Date:** 2026-06-21  
**Spec:** [windows-uac-manifest.md](../specs/windows-uac-manifest.md)

---

## Context

`holodex.exe` was triggering a Windows UAC elevation dialog on every launch during development.
Go does not embed a Windows application manifest by default, so Windows fell back to its
installer-detection heuristic (triggered by substrings like "install", "setup", "update" in
the binary path or metadata) and/or treated the unsigned binary as potentially requiring
elevation.

The fix is to embed an explicit manifest declaring `requestedExecutionLevel = asInvoker`,
which tells Windows to run the process at the caller's existing privilege level with no
elevation prompt.

## Decision

Embed an `asInvoker` application manifest via a compiled Windows resource (`.syso`) in the
`cmd/holodex/` main package directory.

**Approach:**
1. `cmd/holodex/holodex.manifest` — the manifest source XML, committed for auditability.
2. `cmd/holodex/holodex_windows_amd64.syso` — compiled resource, generated by
   [`github.com/akavel/rsrc`](https://github.com/akavel/rsrc) and **committed to the repo**
   so a fresh clone builds correctly without installing extra tooling.
3. `//go:generate rsrc -manifest holodex.manifest -arch amd64 -o holodex_windows_amd64.syso`
   in `cmd/holodex/main.go` for reproducible regeneration.
4. The `_windows_amd64.syso` filename suffix causes Go to ignore the file on all non-Windows
   targets — Linux and macOS builds are byte-for-byte unaffected.

**Toolchain:** `rsrc` (manifest-only). `goversioninfo` was considered but not chosen because
the project does not currently need embedded version metadata or an application icon, and
`rsrc` has minimal surface area.

**Admin-rights audit:** `holodex.exe` writes only to user-configurable paths (`DATA_PATH`,
`MEDIA_PATH`, thumbnail dir, person-image dir). No writes to `Program Files`, `HKLM`, raw
sockets, or system services. `asInvoker` is safe — no previously-elevated operations will
silently fail.

## Consequences

**Positive:**
- UAC prompt eliminated for standard-user development runs.
- Fix ships in the compiled binary; no per-developer machine configuration required.
- Committed `.syso` means `go build` on Windows works from a fresh clone without extra tools.
- Cross-platform builds are unaffected.

**Neutral / trade-offs:**
- A binary `.syso` is committed to the repo. It is small (≈ 1 KB), deterministically
  regenerable from the manifest source, and the only alternative (generate in CI) would
  require every contributor to have `rsrc` installed.
- This does not suppress SmartScreen ("Windows protected your PC") warnings on first run of a
  downloaded binary — that is a separate mechanism (code signing / reputation), out of scope.

**Negative:** none identified.

## Notes for future maintenance

- If `windows/arm64` is ever targeted, add `holodex_windows_arm64.syso` and extend the
  generate directive.
- If embedded version metadata or an icon is wanted later, replace `rsrc` with `goversioninfo`
  and update the generate directive.
- If the process ever requires admin rights (e.g., binding to a privileged port), change
  `level="asInvoker"` to `level="requireAdministrator"` — but prefer solving the underlying
  need without elevation (e.g., use a high-numbered port).
