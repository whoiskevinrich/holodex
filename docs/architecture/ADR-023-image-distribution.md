# ADR-023: Image Distribution — Published GHCR Image + Pull-Based Compose

**Status**: Accepted
**Date**: 2026-06-10
**Deciders**: Project owner

## Context

[ADR-007](ADR-007-docker-structure.md) defines a single multi-stage image and a
`docker-compose.yml` that builds it from source (`build: .`). That file is a **developer**
artifact: it requires the full repo (Dockerfile, `go.mod`, `web/`) and a Go + Node toolchain
on the host. A user wanting to run Holodex on another machine "from only a compose file"
cannot — `docker compose up` against `build: .` fails with no build context.

Self-hosted apps (Jellyfin, Immich, etc.) solve this by publishing a prebuilt image to a
registry and shipping a compose file that **pulls** rather than **builds**. The runtime is
then decoupled from the source tree.

## Decision

1. **Publish the runtime image to GitHub Container Registry (GHCR)** at
   `ghcr.io/whoiskevinrich/holodex` via CI on every push to `main` and every `v*` tag.
2. **Ship a pull-based [`docker-compose.prod.yml`](../../docker-compose.prod.yml)** that
   references the published image. The existing build-based `docker-compose.yml` is retained
   unchanged for local development.
3. **Build multi-arch** (`linux/amd64`, `linux/arm64`) so the image runs on common NAS/ARM
   hosts as well as x86 servers.

### Tagging

Image tags are generated by `docker/metadata-action`:

| Trigger | Tags produced |
|---|---|
| push to `main` | `edge`, `sha-<short>` |
| tag `vX.Y.Z` | `X.Y.Z`, `X.Y`, `X`, `latest` |

`latest` tracks the most recent **release tag**, never an unreleased `main` commit — so a
plain `docker compose up` is reproducible, and `main` builds are reachable only via `edge`.

## Consequences

- A user on another system needs only `docker-compose.prod.yml` (plus their media path):
  `docker compose -f docker-compose.prod.yml up -d`. No source, no toolchain, no local build.
- The image is **public** on GHCR — anyone can pull without auth. The package must be set to
  public visibility once first published (GHCR defaults new packages to private).
- CI publishing needs only the built-in `GITHUB_TOKEN` with `packages: write`; no long-lived
  registry credentials are stored. This is an **infrastructure/access** change and was run
  through `/security-review` (no stored secrets; least-privilege token scope; public-pull,
  authenticated-push).
- A fresh host starts with an empty `holodex-data` volume and re-indexes the library on first
  boot; the named volume must be migrated separately to move an existing index.
- Multi-arch builds use QEMU emulation for `arm64` in CI, lengthening build time. Acceptable
  for the current release cadence; native ARM runners can supersede this later.
- The dev `docker-compose.yml` and ADR-007 build mechanics are unchanged — this ADR adds a
  distribution path alongside them, it does not supersede them.
